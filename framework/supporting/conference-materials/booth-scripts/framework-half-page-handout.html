Open Source Accessibility Framework

Integrate accessibility into your project, one practical step at a time.

30-Second Pitch

A phased framework for open source projects that want to improve accessibility but do not know where to start. Projects work through practical actions in four phases and use a public tracking issue to share progress. It is not a certification, score, or ranking. It supports steady, visible improvement.

Four Phases

  • Foundational: make the commitment visible and track accessibility work.
  • Workflow: build accessibility into everyday project decisions.
  • Testing: add repeatable automated and manual checks.
  • Community: make collaboration accessible and invite people to help.

How to Start

  1. Create a public framework progress issue with the tracking form
    • name
    • repo URL
    • GitHub handle(s)
  2. Foundational phase:
    • add an ACCESSIBILITY.md
    • create an accessibility label
  3. Complete other phases in the order that fits.

Why Adopt It?

  • Clear, achievable steps instead of an overwhelming checklist.
  • Fits existing practices such as labels, pull requests, and triage.
  • Gives contributors well-defined ways to help.
  • Makes progress and remaining barriers visible.
  • Supports shared learning, mentorship, and community feedback.
